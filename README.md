# BioIT-CEITEC/somatic_small_var_call

This repository provides a Snakemake workflow for somatic small variant (SNV and indel) calling. It runs several somatic variant callers in parallel and combines their results into a consensus call set with [SomaticSeq](https://github.com/bioinform/somaticseq). The workflow supports both tumor–normal paired and tumor-only analyses, and both DNA-seq and RNA-seq data. For RNA samples, spliced alignments are processed with GATK `SplitNCigarReads` before variant calling. Individual callers are switched on or off in the configuration file, without modifying the workflow.

## Workflow overview
1. **RNA preprocessing** (RNA only): `SplitNCigarReads` creates `mapped/{sample}.RNAsplit.bam`, which replaces the original BAM in all downstream steps.
2. **Variant calling**: every enabled caller runs independently on each sample (tumor-only) or on each tumor–normal pair.
3. **Consensus**: SomaticSeq merges the caller outputs into `Consensus.sSNV.vcf` and `Consensus.sINDEL.vcf`. It runs in consensus mode, without a trained classifier, with `--minimum-num-callers 0.4`.
4. **Postprocessing**: an R script keeps only `PASS` variants with non-zero tumor depth and VAF (and non-zero normal depth in paired mode). It writes the final variant table `{sample_name}.final_variants.tsv`.

### Variant callers

| Caller | Version | Tumor–normal | Tumor-only |
|---|---|---|---|
| GATK Mutect2 + FilterMutectCalls | 4.1.5.0 | ✓ | ✓ |
| Strelka2 | 2.9.7 | ✓ (somatic workflow) | - |
| VarDict-java | 1.8.3 | ✓ | ✓ |
| LoFreq | 2.1.5 | ✓ | ✓ |
| VarScan2 | 2.4.4 | ✓ | ✓ |
| MuSE | 1.0 | ✓ | – |
| SomaticSniper | 1.0.5 | ✓ | – |

Consensus calling uses SomaticSeq 3.6.2. RNA preprocessing uses GATK 4.3.0.0. In tumor-only mode, MuSE and SomaticSniper are skipped even when they are enabled in the config.

## Requirements
- Linux environment
- Snakemake ≥ 6.0 (the workflow uses `module` / `use rule` and loads the [bioroots_utilities](https://github.com/BioIT-CEITEC/bioroots_utilities) module from GitHub, so internet access is needed at startup)
- Conda / Mamba

Snakemake installs all tool dependencies from the per-rule Conda environments in `wrappers/*/env.yaml`.

## Configuration
The workflow reads `config.json` from the working directory. This file is normally generated by the internal GUI from `workflow.config.json`. Most parameters have defaults there, so you only need to set them manually when running outside the GUI.

### Required parameters
- `globalResources`: path to the global resources directory (reference genomes and annotation).
- `globalTmpdPath`: path to a temporary directory. Strelka run directories are created here.
- `organism`, `assembly` / `reference`: reference genome used for the analysis (e.g. `homo_sapiens`, `GRCh38`). The bioroots_utilities module (`BR.load_organism()`) uses these to resolve the reference files listed under [Reference resources](#reference-resources).
- `lib_ROI`: library / region of interest. `wgs` means whole-genome sequencing; any other value is treated as targeted sequencing (exome or panel), and Strelka then runs with `--exome --callRegions`.
- `tumor_normal_paired` (bool): `true` for tumor–normal paired analysis, `false` for tumor-only analysis.
- `samples`: dictionary of samples. Each sample needs a `sample_name`. In paired mode, each sample also needs:
  - `donor`: patient ID. All samples of one patient share it, and it becomes the name of the analysis output.
  - `tumor_normal`: `tumor` or `normal`.

  Each donor must have exactly one tumor and one normal sample.

### Optional parameters
- `material` (default `DNA`): set to `RNA` to run `SplitNCigarReads` before variant calling.
- `task_name`, `entity_name`: descriptive task and project metadata.

### Caller selection
All callers are enabled in the GUI by default. When running without the GUI, all of these keys must be present in `config.json`:

- `somatic_use_strelka`
- `somatic_use_vardict`
- `somatic_use_mutect2`
- `somatic_use_lofreq`
- `somatic_use_varscan`
- `somatic_use_muse` (paired mode only)
- `somatic_use_somaticsniper` (paired mode only)

### Fine-tuning parameters
- `varscan_extra_params` (default `--strand-filter 0 --p-value 0.95 --min-var-freq 0.05`): extra command-line arguments for VarScan2. Must be present in `config.json` when running without the GUI.
- `min_variant_frequency` (default `0`): minimum allele frequency (a fraction between 0 and 1, e.g. `0.05`) passed to VarDict's `var2vcf` (`-f`). The final variant table is **not** filtered by this value.

### Reference resources
The bioroots_utilities module resolves these resources from the reference configuration:

- `organism_fasta`: reference FASTA, with `.fai` index
- `organism_dict`: sequence dictionary (`.dict`)
- `organism_dna_panel`: BED file of target regions, plus a bgzipped and tabix-indexed copy (`.bed.gz`, `.bed.gz.tbi`) for Strelka
- `organism_dbsnp`: dbSNP VCF (bgzipped and tabix-indexed)

## Usage
Prepare `config.json` and the input BAM files in the working directory, then run:

```bash
snakemake --snakefile <path_to_repo>/Snakefile --use-conda --cores <N>
```

### Required inputs
- `mapped/{sample}.bam` and `mapped/{sample}.bam.bai`: coordinate-sorted, indexed BAM files from an upstream alignment pipeline (DNA-seq or RNA-seq). The read group `SM` tag must match the `sample_name` in the config, because Mutect2 selects samples by this name.

## Output
In the paths below, `{sample_name}` is the sample name in tumor-only mode and the `donor` in paired mode.

### Main output
- `somatic_varcalls/{sample_name}.final_variants.tsv`: final consensus variant table, with one row per `PASS` variant. Columns:

  | Column | Description |
  |---|---|
  | `var_name` | `chrom_position_ref/alt`. Indels are written without the anchor base, with `-` for the empty allele. |
  | `tumor_variant_freq` | variant allele frequency in the tumor |
  | `tumor_depth` | read depth in the tumor |
  | `normal_variant_freq` | variant allele frequency in the normal (paired mode only) |
  | `normal_depth` | read depth in the normal (paired mode only) |
  | `number_of_callers` | number of callers that reported the variant |
  | `callers` | comma-separated list of callers that reported the variant |
  | `tumor_fwd_strand_pct` | fraction of tumor reads on the forward strand |
  | `normal_fwd_strand_pct` | fraction of normal reads on the forward strand (paired mode only) |

- `somatic_varcalls/{sample_name}.filtered_out_variants.tsv`: variants from the SomaticSeq consensus that were removed by the final filtering. Same columns as the final table, plus `filter_reason`, a comma-separated list of every filter the variant failed:
  - `FILTER=<value>`: SomaticSeq FILTER is not `PASS` (e.g. `FILTER=LowQual`, `FILTER=REJECT`)
  - `no_tumor_depth`: tumor depth is zero or missing
  - `no_tumor_vaf`: tumor VAF is zero or missing
  - `no_normal_depth`: normal depth is zero or missing (paired mode only)

### Intermediate outputs
- `somatic_varcalls/{sample_name}/Consensus.sSNV.vcf`, `Consensus.sINDEL.vcf`: SomaticSeq consensus VCFs, including non-`PASS` variants.
- `somatic_varcalls/{sample_name}/{caller}/`: raw VCF output of each caller (`mutect2/`, `strelka/`, `vardict/`, `lofreq/`, `varscan/`, `muse/`, `somaticsniper/`).
- `mapped/{sample}.RNAsplit.bam` (+ `.bai`): RNA only, the BAM after `SplitNCigarReads`.

### Additional outputs
- `logs/{sample_name}/callers/{caller}.log`: log of each variant caller.
- `logs/{sample_name}/somaticseq.log`, `logs/{sample_name}/postprocess_somaticseq_variants.log`: logs of consensus calling and postprocessing.
- `config.json`: snapshot of the configuration used for the run.
